По условию лабораторной работы сценарий должен обрабатывать параметры командной строки, поддерживать справку, трассировку и корректно реагировать на ошибочные ситуации.

> [!NOTE]

# Отчет по лабораторной работе №21 по курсу "Фундаментальная информатика"

**Тема:** Командные файлы shell. Bash-сценарии.

**Цель:** Освоить написание сценариев командного интерпретатора, обработку параметров командной строки и работу с файловой системой средствами shell.

**Задание:** Удаление файлов, суммарная длина которых не меньше заданного числа блоков.

> **Вариант 25:** Удаление файлов, суммарная длина которых не меньше заданного числа блоков.

## Идея и метод решения

Скрипт получает входные параметры, проверяет их корректность, затем просматривает файлы в указанном каталоге и определяет их размер в блоках.

После этого файлы последовательно добавляются в список на удаление. Для каждого выбранного файла его размер прибавляется к общей сумме. Как только сумма становится не меньше заданного числа блоков, выбранные файлы удаляются.

Такой подход позволяет не удалять файлы сразу при обходе каталога. Сначала формируется набор файлов, и только после достижения нужной суммы выполняется удаление.

> [!IMPORTANT]
> В этой задаче важно не перепутать условие: нужно удалить не один файл нужного размера, а набор файлов, суммарная длина которых не меньше заданного числа блоков.

## Структура программы

Логически сценарий можно разделить на несколько частей:

- разбор параметров командной строки
- вывод справки при запросе пользователя
- включение трассировки для отладки
- проверка существования каталога
- проверка заданного числа блоков
- поиск файлов в каталоге
- вычисление размера каждого файла в блоках
- накопление общей суммы
- удаление выбранных файлов
- обработка ошибочных ситуаций

Такое разделение важно, потому что удаление файлов является необратимой операцией. Перед вызовом удаления нужно убедиться, что параметры корректны, каталог существует, а список файлов выбран правильно.

## Алгоритм

1. Считать параметры командной строки
2. Если запрошена справка, вывести описание использования скрипта
3. Если включена трассировка, активировать вывод выполняемых команд
4. Проверить, что заданный путь существует и является каталогом
5. Проверить, что число блоков является корректным положительным числом
6. Найти файлы, подходящие для обработки
7. Для каждого файла определить размер в блоках
8. Добавить файл в список на удаление и увеличить накопленную сумму
9. Остановить выбор файлов, когда сумма стала не меньше заданного числа блоков
10. Если нужная сумма набрана, удалить выбранные файлы
11. Если нужная сумма не набрана, вывести сообщение и не выполнять некорректное удаление

## Тонкости реализации

Основная сложность была в том, чтобы сделать удаление достаточно безопасным. Команда удаления сама по себе простая, но ошибка в выборе файлов может привести к потере лишних данных.

Самые важные моменты:

- нужно считать именно суммарный размер выбранных файлов
- размер должен сравниваться с заданным числом блоков
- нельзя продолжать выбирать файлы после достижения нужной суммы
- перед удалением нужно проверить, что список файлов не пустой
- нужно отличать обычные файлы от каталогов
- нужно корректно обрабатывать пустой каталог
- нужно учитывать файлы, для которых может не хватить прав доступа
- нужно не ломаться на некорректных параметрах

> [!IMPORTANT]
> Особое внимание нужно уделить именам файлов. В shell легко случайно сломать обработку файлов с пробелами в имени, если неправильно использовать переменные и подстановки.

Кратко про обработку ошибок: сценарий должен обрабатывать несуществующий каталог, неправильное число параметров, некорректное значение числа блоков, пустой каталог, отсутствие подходящих файлов и ошибки доступа. В таких случаях скрипт должен вывести понятное сообщение и не выполнять опасные действия.

> [!NOTE]
> При отладке удобно использовать трассировку: она позволяет увидеть, какие команды выполняются и какие значения получают переменные во время работы скрипта.

## Сложность

Основная операция сценария - обход файлов в каталоге. Если в каталоге находится `n` файлов, то в худшем случае нужно проверить каждый из них.

| **Операция** | **Сложность** |
|:------------|:--------------|
| обход файлов | `O(n)` |
| подсчет суммарного размера | `O(n)` |
| удаление выбранных файлов | `O(k)`, где `k` - количество удаляемых файлов |
